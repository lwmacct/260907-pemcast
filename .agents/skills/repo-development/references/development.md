# pemcast development

## Baseline

```bash
go test ./...
go run ./cmd/pemcast --help
go run ./cmd/pemcast config example
go run ./cmd/pemcast --config config/config.yaml config validate
```

There is no visible lint task or PR test workflow. Run the full suite locally.

## Generated config

`config/config.example.yaml` is generated by `internal/config` tests and checked in. After schema, default, description, type, or cfgm-option changes, run `go test ./internal/config`, then commit the updated example. Do not edit it as source of truth.

Environment values use full schema paths such as `PEMCAST_AGENT_ETCD_ENDPOINTS`. Structs, slices, and maps are JSON; scalars and durations are strings.

## Change map

- CLI/lifecycle: inspect `cmd/pemcast`, `internal/appcmd/agent`, and `internal/appcmd/config`. Preserve signal cancellation and once/watch behavior.
- Configuration: edit `internal/config/config.go` and `validation.go`, then cover path safety, modes, durations, uniqueness, and mapping references.
- Remote protocol: preserve safe names, 4 MiB limit, unknown-key rejection, exact file-set verification, and revision `snapshot + 1` watch. Add focused or local-etcd tests; `internal/etcdsource` has none.
- Bundle validation: keep digests independent from etcd and deployment. Test manifest rejection, digest ordering, missing/extra files, key mismatch, and validity boundaries.
- Reconciliation: `internal/reconcile` has no direct tests. Cover changed/unchanged digest, dry-run, hook retry, state updates, concurrency, missing snapshot targets, and both delete policies.
- Deployment: preserve staging, fsync, rename, content-addressed releases, atomic relative symlink switch, and active-release retention.
- Hook/state: preserve direct execution, event schema, timeout, output truncation, strict JSON, and atomic state writes.

The concrete deployer, hook, and state parameters make reconcile isolation awkward. Extract interfaces only when materially needed for tests.

## Build and release

```bash
go build ./cmd/pemcast
```

The publish workflow builds a static linux/amd64 binary, injects version variables, compresses it with UPX, verifies the version, builds and pushes GHCR image metadata, and may deploy. Do not manually edit generated version metadata.

Before handoff, run `gofmt` on edited Go files, focused tests, `go test ./...`, affected CLI/config checks, and inspect generated config changes. Update the matching skill reference and README for protocol or deployment behavior changes.
